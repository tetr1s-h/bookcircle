# BookCircle — книжный клуб и обмен книгами

Семестровый проект (вариант 11). Студенты ведут общий каталог книг, добавляют на «полку» свои
экземпляры, одалживают их друг другу, ведут список чтения и пишут рецензии.

**Стек:** Python 3.10+, FastAPI, Jinja2 (серверные шаблоны), SQLite (стандартный модуль `sqlite3`),
SQL-миграции, `unittest` для тестов. Дизайн — один CSS-файл, без JS-фреймворков.

## Быстрый старт

Нужен Python 3.10 или новее (`python --version`).

**Windows (PowerShell)**
```powershell
cd bookcircle
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python manage.py setup
python manage.py run
```

**Linux / macOS**
```bash
cd bookcircle
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python manage.py setup
python manage.py run
```

Откройте http://127.0.0.1:8000

Что делает `setup`: создаёт файл `bookcircle.db`, применяет миграции (`migrations/*.sql`) и наполняет
базу демо-данными. Повторный запуск `setup` на непустой базе остановится с сообщением —
для чистого старта используйте `python manage.py reset` (удаляет базу и создаёт заново).

Если `Activate.ps1` не запускается в PowerShell: `Set-ExecutionPolicy -Scope Process Bypass`.

## Команды

| Команда | Действие |
|---|---|
| `python manage.py migrate` | применить миграции |
| `python manage.py seed` | демо-данные (на пустой базе) |
| `python manage.py setup` | migrate + seed |

## Тесты

```bash
python -m unittest discover -s tests -v
```

* `test_services.py` — бизнес-правила: независимое бронирование двух экземпляров, полный цикл
  обмена, невозможность принять двух заёмщиков (в т.ч. на уровне БД), запрещённые переходы (409),
  права (403/404), редактирование отзыва без дубля, рейтинг без скрытых, статистика месяца, роли.
* `test_templates.py` — все страницы рендерятся на демо-данных.
* `test_web.py` — сквозные проверки через HTTP (редиректы, 403/404, формы, PUT-маршруты);
  требует установленные зависимости из `requirements.txt`, иначе пропускается.

## Структура

```
manage.py              команды управления
migrations/001_init.sql   схема БД: таблицы, индексы, ограничения, триггер
app/
  main.py              приложение, обработчики ошибок (403/404/409…)
  db.py                соединение SQLite, транзакции, миграции
  services/            вся бизнес-логика (users, books, copies, loans, reading, reviews)
  routes/              HTTP-маршруты (auth, catalog, shelf, admin) и проверки ролей (deps.py)
  templates/           Jinja2-шаблоны
  static/              style.css, app.js
  seed.py              демо-данные
tests/                 тесты
docs/ER.md             ER-диаграмма и обоснование изменений модели
```

Логика отделена от маршрутов: маршруты разбирают форму и вызывают функции из `services/`,
которые проверяют права и правила и бросают `AppError` с кодом и понятным сообщением.

## Маршруты

| Маршрут | Назначение |
|---|---|
| `GET /books` | каталог: поиск, жанр, «только доступные», пагинация |
| `GET /books/{id}` | книга: экземпляры, рейтинг, отзывы |
| `POST /copies` | добавить свой экземпляр |
| `POST /copies/{id}/loans` | запросить экземпляр с датой возврата |
| `POST /loans/{id}/accept` | владелец принимает запрос (остальные отклоняются) |
| `POST /loans/{id}/hand-over` | отметить передачу |
| `POST /loans/{id}/return` | отметить возврат |
| `POST /loans/{id}/reject` · `/cancel` | отклонить / отменить |
| `PUT` (или `POST`) `/reading/{book_id}` | статус чтения |
| `PUT` (или `POST`) `/books/{id}/review` | создать или изменить отзыв |

Браузерные формы умеют только GET/POST, поэтому «PUT»-маршруты принимают и `PUT`, и `POST` —
страницы используют `POST`, а `PUT` можно вызвать, например, через `curl -X PUT`/тесты.
Остальные страницы: `/shelf`, `/loans`, `/reading`, `/moderation/…`, `/admin/users`,
`/login`, `/register`, `/profile`.

**Коды ошибок** (страница с понятным текстом): 400 — ошибка ввода (на формах — сообщения у полей),
401 — нет входа (редирект на `/login`), 403 — нет прав, 404 — не найдено, 409 — недопустимое
состояние (запрещённый переход, занятый экземпляр и т.п.).

## Как это закрывает критерии приёмки

| Критерий | Где смотреть |
|---|---|
| Два экземпляра одной книги у разных владельцев бронируются независимо | «Мастер и Маргарита»: экземпляры Анны (свободен) и Бориса (принят запрос). Тест `test_two_copies_are_booked_independently` |
| Принять → передать → вернуть, доступность восстанавливается | Войти как Анна → «Обмены». Тест `test_full_cycle_restores_availability` |
| Нельзя принять двух заёмщиков | У экземпляра Клары (№6) два ожидающих запроса: после принятия одного второй отклоняется. БД блокирует вторую активную передачу индексом `ux_loans_one_active_per_copy` |
| Правка отзыва меняет рейтинг без дубля | Книга → «Мой отзыв» → «Обновить». Тест `test_edit_changes_rating_without_duplicate` |
| Запуск по README на чистой базе | раздел «Быстрый старт» |
| Сценарий через интерфейс, данные сохраняются | SQLite-файл, перезагрузка страницы ничего не теряет |
| Права, ошибки данных, запрещённые переходы | `test_services.py`, `test_web.py` |

## Бизнес-правила (кратко)

* Статусы заявки: ожидает → принята / отклонена / отменена; принята → передана / отменена;
  передана → возвращена. Любое другое действие — 409.
* Принимать, отклонять, отмечать передачу и возврат может только владелец экземпляра; отменять — заёмщик
  (принятую — и владелец).
* Один экземпляр — не более одной принятой/активной передачи: проверка в транзакции `BEGIN IMMEDIATE`
  **и** частичный уникальный индекс в БД.
* Нельзя одолжить себе (сервис + триггер БД). Занятый экземпляр запросить нельзя.
* Принятый или переданный экземпляр нельзя скрыть или удалить; экземпляр с историей обменов
  удалить нельзя вообще (только скрыть).
* Просрочка вычисляется (передана и срок прошёл), в БД не хранится.
* Рейтинг считается без скрытых отзывов; «прочитано за месяц» — по `finished_at`.
* Одна запись чтения и одна рецензия на пару пользователь/книга; рецензию можно редактировать.
* Назначать роли может только администратор; администратор не может менять роль самому себе.

## Подготовка к защите

1. Откройте `docs/ER.md` — диаграмма и таблица «что изменено и почему».
2. Покажите сценарии из таблицы критериев на демо-аккаунтах (вход в разных вкладках/окнах инкогнито).
3. Покажите `migrations/001_init.sql`: индексы, `UNIQUE`/`CHECK`, частичный индекс и триггер.
4. Запустите тесты — должны быть зелёными.
5. Заполните карточку выбора (участники, репозиторий, дата защиты) в задании.
